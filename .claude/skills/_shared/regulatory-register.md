# AI regulatory register (ai-automation department)

*Owner: ai-manager. v0.1.0, built 2026-11-08 from the department's original research files (internal, not included in this repo)
(Regulatory register table, sections A1 to A3). Every row carries a source URL and a date checked.
This file is ground-truth tier 2 in `engagement-conventions.md` section 3.*

**Tags kept exactly as the research has them.** `[secondary]` means only a law-firm note, vendor
blog or trade press confirmed the fact; it is never upgraded to fact here. `PENDING_VERIFICATION`
means the research could not confirm it; it does not go into a client deliverable until closed.

**Status vocabulary (conventions section 4).** Every row is one of: **In force**, **Commenced
later** (binding, with a start date still ahead), **Proposed** (bill, draft, consultation,
shelved), **Voluntary** (guidance, standard or policy with no legal force for the client).
Regulator reports and supervisory letters are labelled **Supervisory expectation**: not law in
themselves, but they signal how existing binding duties will be enforced.

## Re-verify cadence

- **Monthly**, by the CTO weekly scan's first run of each month: re-check every row marked
  Proposed, Commenced later or `PENDING_VERIFICATION`, plus every row whose date checked is
  older than 60 days.
- **Before client use**: any row older than 60 days is re-verified against its source (or a
  primary source in conventions section 3) before it appears in a client deliverable. Update the
  `Date checked` cell when you do; if the source changed, change the row and add a line to the
  change log at the bottom.
- Never edit a status from memory. If a primary source cannot be reached, leave the row as is and
  mark the deliverable item `PENDING_VERIFICATION`.
